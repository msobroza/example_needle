# Continue.dev demo: code-aware chat over needle + the playbook

This repo doubles as a demo workspace for [Continue](https://continue.dev)
with two integrations, both wired by a single command:

* **[pydocs-mcp](https://pypi.org/project/pydocs-mcp/)** — two MCP servers
  giving Continue `search` / `lookup` tools over **(a)** example_needle's own
  source and **(b)** a sibling
  [coding-agent-playbook](../../coding-agent-playbook/coding-agent-playbook)
  checkout. Both index **project files only** (`--skip-deps`, no dependency
  indexing) with dense embeddings from **`Qwen/Qwen3-Embedding-0.6B`**.
* **coding-agent-playbook (`cap`)** — generates the Continue **rules**
  (`.continue/rules/`) and **slash prompts** (`.continue/prompts/`, e.g.
  `/explain`, `/review`) plus a universal `AGENTS.md`.

## Prerequisites

* [uv](https://docs.astral.sh/uv/) and Python ≥ 3.12 (uv fetches it).
* A sibling checkout of the playbook next to this repo:

  ```text
  Projects/
  ├── example_needle/                      # this repo
  └── coding-agent-playbook/
      └── coding-agent-playbook/           # cap engine (not on PyPI yet)
  ```

* While the temporary `pydocs-mcp` git source in `pyproject.toml` is active
  (until 0.3.1 reaches PyPI), building it needs a Rust toolchain (`cargo`).
  Once the release is out, delete that one line under `[tool.uv.sources]`
  and re-sync — no Rust needed after that.
* **Apple Silicon:** make sure `uv` itself is a native arm64 build. An
  x86_64 uv (e.g. from an Intel-era Anaconda) resolves for the wrong platform
  and fails on `onnxruntime` / `torch` wheels. If you hit that, create the
  venv explicitly first: `uv venv --python cpython-3.12-macos-aarch64-none`.

## Setup (three commands)

```bash
uv sync --group demo        # installs needle-demo, pydocs-mcp, cap
uv run needle-demo init     # Continue config + MCP overlay + playbook init
uv run needle-demo index    # pre-build both indexes (one-time model download)
```

`init` is idempotent — re-running it regenerates the configs and routes the
playbook through `cap sync`. `index --force` rebuilds the caches from scratch.

### What `init` writes

| File | Purpose |
| --- | --- |
| `.continue/mcpServers/needle-docs.yaml`, `.continue/mcpServers/playbook-docs.yaml` | Continue MCP block files declaring the two pydocs-mcp servers (absolute paths into `.venv`). |
| `.continue/pydocs-mcp.yaml` | pydocs-mcp overlay: `sentence_transformers` provider, `Qwen/Qwen3-Embedding-0.6B`, dim 1024. Shared by both servers. |
| `.continue/rules/*.md` | Generated by cap (project context, Python house style, error handling, pytest). |
| `.continue/prompts/*.md` | Generated by cap (`/explain`, `/generate-tests`, `/refactor`, `/review`). |
| `AGENTS.md`, `.coding-agent-playbook.toml`, `.pre-commit-config.yaml` | cap's universal rules file, its config, and a `cap sync --check` drift hook. |

Models are *not* configured here — Continue merges this workspace file with
your global `~/.continue` config, so your existing chat models keep working.

## Using it

Open this repo in VS Code with the Continue extension and reload. Continue
spawns both MCP servers (first launch re-indexes; after `needle-demo index`
that's a sub-second cache hit). Then:

* *"Which class implements late-interaction scoring?"* — the model calls
  `needle-docs` → `search` / `lookup` over this repo's code and docs.
* *"How do playbook adapters render Continue rules?"* — same, via
  `playbook-docs` over the cap checkout.
* `/explain`, `/review`, … — the cap-generated prompts, with the rules from
  `.continue/rules/` applied to every conversation automatically.

## How the servers are wired

Each block file in `.continue/mcpServers/` runs the venv binary directly:

```yaml
name: needle-docs
version: 0.0.1
schema: v1
mcpServers:
  - name: needle-docs
    type: stdio
    command: <repo>/.venv/bin/pydocs-mcp
    args: [--config, <repo>/.continue/pydocs-mcp.yaml,
           serve, <project-to-index>, --skip-deps, --no-inspect]
```

* `--skip-deps` — index only the project's own `.py` / `.md` / `.ipynb`
  files, never its installed dependencies.
* `--no-inspect` — static parsing; nothing is imported, no side effects.
* `--config` — the Qwen3 embedding overlay; everything else uses pydocs-mcp's
  shipped defaults. Caches live under `~/.pydocs-mcp/`, one SQLite + `.tq`
  pair per indexed project.

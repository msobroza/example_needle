# RAG load test with Locust — design

Date: 2026-09-09
Status: approved under stated assumptions (autonomous session; see "Assumptions")
Location of the new code: `rag_load_test/` (top-level directory of this monorepo)

## 1. Goal

Add a self-contained sub-project that lets us **load test the same RAG workflow
under three deployment topologies on Domino Data Lab 6.2** and compare them:

| Topology | Domino apps | What runs where |
| --- | --- | --- |
| `monolith` | 1 | embedder + Chroma + reranker + LangGraph workflow + OpenAI client, all in one FastAPI process |
| `split-reranker` | 2 | app A: OpenVINO Model Server (OVMS) serving the reranker; app B: workflow + embedder + Chroma |
| `split-all` | 3 | app A: OVMS reranker; app C: OVMS embedder; app B: workflow + Chroma (calls A and C over HTTP) |

The workflow code is **identical** in all topologies. Only the transport behind
the `EmbedderPort` and `RerankerPort` changes (in-process model vs HTTP call to
OVMS). That is what makes the comparison apples-to-apples.

Locust drives `POST /query` (full RAG) and `POST /retrieve` (retrieval only)
against each deployment, records per-stage latencies, and a small script turns
the Locust CSVs into a markdown comparison table.

## 2. Assumptions (decisions taken without a user round-trip)

| Question I would have asked | Decision |
| --- | --- |
| Directory / package name | `rag_load_test/` with importable package `rag_load_test` and its own `pyproject.toml`; it does **not** import `needle`/`needle_core`. |
| Embedding model | `BAAI/bge-small-en-v1.5` (sentence-transformers locally; `embeddings_ov` export for OVMS). |
| Reranker model | `BAAI/bge-reranker-base` (sentence-transformers `CrossEncoder` locally; `rerank_ov` export for OVMS). |
| LLM | OpenAI Chat Completions, default `gpt-4o-mini`; `OPENAI_BASE_URL` honoured so a Domino AI Gateway endpoint can be substituted. A `fake` LLM backend exists so load tests can isolate retrieval cost. |
| Corpus | Deterministic synthetic corpus (fictional company handbook) generated by code, plus a JSONL loader for a real corpus. |
| Load shape | Locust `FastHttpUser`, headless runs with fixed users/spawn-rate/duration; optional step-load shape. |
| Domino app entry points | `app.sh`-style shell scripts binding `0.0.0.0:8888` (Domino requirement); tracing via `domino.agents.tracing.add_tracing` when `dominodatalab[agents]` is installed, no-op otherwise. |
| OVMS version | Docker image `openvino/model_server:2026.3.1`; binary `ovms_ubuntu22_2026.3.1_python_off.tar.gz` for the Domino environment. Pinned in one place (`ovms/versions.env`). |
| Python | `>=3.10` like the root project; developed against 3.11. |
| Git | Nothing is committed in this session; the user commits. |

## 3. Approaches considered

1. **One package, pluggable adapters, topology chosen by env vars (chosen).**
   Same FastAPI app for every topology; `RAG_EMBEDDER_BACKEND` / `RAG_RERANKER_BACKEND`
   pick `local` or `ovms`. Guarantees identical workflow code across topologies,
   least code, one test suite.
2. Separate packages per app (monolith app, workflow app, shared lib). More
   files, and the two apps drift over time, which silently invalidates the comparison.
3. Reuse the `needle` page-image retrievers as the retrieval layer. Rejected:
   the user asked for a text RAG (sentence-transformers + Chroma), and importing
   `needle` would drag torch into the workflow app's import path.

## 5. Contracts (ports and models)

```python
class Passage(BaseModel):        id: str; text: str; metadata: dict[str, str | int | float | bool]
class ScoredPassage(Passage):    retrieval_score: float; rerank_score: float | None = None
class StageTimings(BaseModel):   embed_ms: float; retrieve_ms: float; rerank_ms: float; generate_ms: float; total_ms: float
class RagResult(BaseModel):      question: str; answer: str | None; passages: list[ScoredPassage]; timings: StageTimings

class EmbedderPort(Protocol):
    async def embed_query(self, text: str) -> list[float]: ...
    async def embed_documents(self, texts: Sequence[str]) -> list[list[float]]: ...
    async def ready(self) -> tuple[bool, str]: ...          # (ok, detail) for /readyz
    @property
    def model_name(self) -> str: ...
class RerankerPort(Protocol):
    async def rerank(self, query: str, passages: Sequence[ScoredPassage], top_n: int) -> list[ScoredPassage]: ...
    async def ready(self) -> tuple[bool, str]: ...
class VectorStorePort(Protocol):
    async def upsert(self, passages: Sequence[Passage], embeddings: Sequence[Sequence[float]]) -> None: ...
    async def query(self, embedding: Sequence[float], top_k: int) -> list[ScoredPassage]: ...
    async def count(self) -> int: ...
class ChatModelPort(Protocol):
    async def generate(self, messages: list[dict[str, str]]) -> str: ...
```

Every port is `async`. CPU-bound adapters (sentence-transformers, Chroma
`PersistentClient`) run their sync calls in a **bounded** `ThreadPoolExecutor`
(`RAG_MODEL_THREADS`, default 4) via `loop.run_in_executor`, so the event loop
never blocks and the process cannot fork-bomb itself under load.

## 7. Workflow (LangGraph)

```
embed_query ──► retrieve ──► rerank ──► (mode == "query") ──► generate ──► END
                                   └──► (mode == "retrieve") ─────────────► END
```

* `RagState` (TypedDict): `question`, `mode` (`query`|`retrieve`), `top_k`,
  `rerank_top_k`, `query_embedding`, `candidates`, `reranked`, `answer`,
  `timings_ms` (dict).
* Each node is produced by a factory that closes over `RagDependencies` and
  wraps the body with a timer that writes `timings_ms[<stage>]`.
* `rerank` with `RAG_RERANKER_BACKEND=none` passes the top `rerank_top_k`
  candidates through unchanged (rerank_ms ≈ 0) so the topology comparison can
  also show the cost of reranking itself.
* `generate` builds messages from `prompts.build_rag_messages` (system prompt +
  numbered passages, ask for `[n]` citations) and calls `ChatModelPort`.
* Graph is compiled once at app startup (`lifespan`) and invoked with `ainvoke`.

## 8. HTTP API (FastAPI, async)

| Route | Body / result |
| --- | --- |
| `POST /query` | `{question, top_k?, rerank_top_k?}` → `{request_id, deployment, answer, passages[], timings_ms{embed,retrieve,rerank,generate,total}}` |
| `POST /retrieve` | same request → same response minus `answer` (generate skipped) |
| `GET /healthz` | `{"status":"ok"}` liveness |
| `GET /readyz` | checks: collection count > 0, OVMS endpoints reachable when configured → 200 or 503 with per-check detail |

* `root_path` is taken from `DOMINO_RUN_HOST_PATH` (Domino reverse proxy prefix)
  so the OpenAPI docs resolve behind the proxy; routes stay at `/`.
* Response headers: `X-RAG-Topology`, `X-Request-ID`.
* Errors: `RagDependencyError` → 503 `{"error":"<component>_unavailable","detail":...}`;
  upstream timeouts → 504; pydantic validation → 422 (FastAPI default).
* `/query` handler is decorated with `traced("rag_query")` which resolves to
  `domino.agents.tracing.add_tracing(name=..., autolog_frameworks=["langchain"])`
  when `RAG_DOMINO_TRACING=true` and the package imports, otherwise identity.
* Structured JSON logs (one line per request: request_id, topology, mode,
  timings, status).

## 9. Ingestion

`rag-ingest [--synthetic N | --corpus file.jsonl] [--seed 1234] [--chunk-words 120 --overlap-words 20]`

1. Load documents (`{"id","title","text","metadata"}` per JSONL line) or
   generate the synthetic corpus (default 200 documents).
2. Chunk by word windows → `Passage(id=f"{doc_id}:{i}", metadata={doc_id,title,chunk})`.
3. Embed in batches of 64 with the configured `EmbedderPort` (must match the
   embedder used at query time; the collection stores the embedder model name
   in its metadata and `/readyz` warns on mismatch).
4. Upsert into Chroma (idempotent).

`locust/questions.py` derives ~50 questions from the same synthetic templates so
retrieval hits are meaningful.

## 10. Locust

* `RagUser(FastHttpUser)`: `wait_time = between(0.2, 1.0)`; tasks `query`
  (weight from `RAG_LOADTEST_QUERY_WEIGHT`, default 1) and `retrieve`
  (`RAG_LOADTEST_RETRIEVE_WEIGHT`, default 3).
* Auth headers: `RAG_LOADTEST_BEARER_TOKEN` → `Authorization: Bearer …`, or
  `DOMINO_API_KEY` → `X-Domino-Api-Key: …` (Domino apps require one of these
  when called from outside a Domino run).
* After each successful call the user parses `timings_ms` and fires one extra
  Locust request event per stage with `request_type="STAGE"` and
  `name=f"{endpoint}:{stage}"` so p50/p95/p99 per stage appear in the same stats
  CSV as the endpoint totals.
* Failures: non-200 or unparsable JSON mark the request failed with the body
  excerpt.
* `shapes.StepLoadShape` (5→10→20→40 users, 60 s each) is registered only when
  `RAG_LOADTEST_SHAPE=step`.
* The locustfile lives at `loadtest/locustfile.py` (the directory is not named
  `locust` so it can never shadow the installed package); all logic that does
  not need gevent lives in `rag_load_test.loadtest.helpers` and is unit-tested.
* `scripts/run_loadtest.sh <run-name> <host> [users=20] [spawn=5] [time=2m]`
  writes `results/<run-name>_stats.csv`, `_failures.csv`, `.html`.
* `scripts/compare_runs.py results/monolith results/split-reranker results/split-all --out results/comparison.md`
  reads each `<prefix>_stats.csv` and prints a markdown table per endpoint and
  per stage: requests, failure %, RPS, p50, p95, p99, and delta vs the first
  run. No external deps (csv module only).

## 11. OVMS

* `ovms/export_models.sh` (needs the `[ovms-export]` extra): downloads
  `export_model.py` from the OVMS repo at the pinned tag, then runs
  `rerank_ov --source_model BAAI/bge-reranker-base --model_name bge-reranker-base --weight-format int8 --config_file_path ovms/models/config_reranker.json --model_repository_path ovms/models`
  and
  `embeddings_ov --source_model BAAI/bge-small-en-v1.5 --model_name bge-small-en-v1.5 --pooling CLS --weight-format int8 --config_file_path ovms/models/config_embedder.json --model_repository_path ovms/models`.
* `ovms/docker-compose.yml`: two services on `openvino/model_server:${OVMS_VERSION}`:
  reranker `--rest_port 8001 --config_path /workspace/config_reranker.json`,
  embedder `--rest_port 8002 --config_path /workspace/config_embedder.json`.
* Adapter request/response shapes follow the OVMS docs:
  rerank `{"model","query","documents","top_n"}` → `{"results":[{"index","relevance_score"}]}`;
  embeddings `{"model","input":[...]}` → `{"data":[{"index","embedding"}]}`.
  Results are re-ordered by `index` so document order never depends on server order.

## 12. Domino 6.2 deployment

* Every Domino app binds `0.0.0.0:8888`; the entry-point scripts `cd` to
  `rag_load_test/` and export the topology env vars before exec'ing uvicorn or
  `ovms`.
* `app_ovms_*.sh` expect the exported models in a Domino Dataset mounted at
  `RAG_OVMS_MODELS_DIR` (default `/mnt/data/ovms-models`) so model files are
  not committed; the `Dockerfile.ovms` environment snippet installs the pinned
  ovms binary tarball.
* App-to-app calls inside Domino: the workflow app sets `RAG_OVMS_AUTH=domino`
  and the `DominoAccessToken` provider fetches a bearer token from
  `http://localhost:8899/access-token`, caching it for 4 minutes (tokens expire
  after ~5 minutes) and refreshing on 401.
* Tracing: install `dominodatalab[agents]` (the `[domino]` extra) and set
  `RAG_DOMINO_TRACING=true`; deploy from the Apps view or from an Experiment
  run via **Deploy Agent** — same hosting, agent deployment only changes the
  dashboard/traces association.
* `domino/README.md` lists, per topology, which apps to publish, which entry
  point, which env vars, the hardware tier suggestion (CPU tier with ≥4 cores
  for OVMS int8 models), and how to run Locust either from a Domino Workspace
  (bearer token) or from a laptop (API key).

## 13. Error handling & robustness (explicit, per repo rule)

* All network calls have timeouts; OVMS and OpenAI calls have bounded retries
  (2) with short exponential backoff. No circuit breakers or rate limiting
  (not requested by the project rules).
* Adapter errors are wrapped in `RagDependencyError(component, detail)` carrying
  the URL/model that failed.
* Local model loading happens in `lifespan` so a broken model fails fast at
  startup rather than on first request; `/readyz` reflects readiness.
* Thread pool is bounded (`RAG_MODEL_THREADS`) so overload degrades into
  queueing, not process exhaustion.

## 14. Testing (headless, `make test` inside `rag_load_test/`)

* `tests/test_settings.py` — defaults, env overrides, invalid backend error message.
* `tests/test_workflow_graph.py` — graph with fakes: query vs retrieve modes,
  timings populated, reranker `none` passthrough, ordering by rerank score.
* `tests/test_api.py` — `httpx.AsyncClient(ASGITransport)`: `/query`,
  `/retrieve`, `/healthz`, `/readyz` (ready and not-ready), 503 mapping, headers.
* `tests/test_ovms_adapters.py` — `httpx.MockTransport`: payload shape,
  index re-ordering, retry on 503 then success, timeout → `RagDependencyError`,
  bearer header from static and Domino token providers (token endpoint mocked).
* `tests/test_local_adapters.py` — `SentenceTransformerEmbedder` /
  `CrossEncoderReranker` with an injected fake model object (no weights).
* `tests/test_chroma_store.py` — `EphemeralClient` round trip (upsert twice is idempotent, query order).
* `tests/test_ingest.py` — chunking, synthetic corpus determinism, CLI with fakes.
* `tests/test_loadtest_helpers.py` — stage-event extraction, header selection, question bank
  (locust itself is imported only by `loadtest/locustfile.py` and `shapes.py`;
  `tests/conftest.py` sets `LOCUST_SKIP_MONKEY_PATCH=1` so importing them in
  tests cannot gevent-patch the interpreter).
* `tests/test_compare_runs.py` — sample CSV fixtures → markdown table content.
* `tests/test_fake_chat.py` — deterministic output, latency honoured.
* Nothing downloads weights or needs network; `sentence-transformers`,
  `chromadb`, `langgraph`, `locust` are installed in the `[dev]` extra but only
  fakes are exercised.

## 16. Out of scope

Streaming responses, multi-turn chat, real corpora beyond the JSONL loader,
GPU tiers, Kubernetes manifests outside Domino, and any change to `needle`.
